# 一笔 · EULERTRAIL

在格点上把每条边都描一遍，边不许重复。每一关的"最少几笔"不是卡片上印的估计值，而是欧拉定理的结论：

> 一个连通图的边，最少能拆成 `k = max(1, 奇点数 / 2)` 条互不重复的迹（trail）覆盖，且不可能更少。

下界有证明（每条迹只有两个端点，奇度点必须是某条迹的端点 ⇒ `2k ≥ odd`），上界有构造（奇点两两配对加虚边 →
欧拉回路 → 按虚边切开）。所以屏幕上的**笔数上限是定理**，不是搜索预算的副产品 —— 而本仓把下界、上界、
穷举三条路都实现了，并且要求它们在同一关上给出同一个数。

**线上可玩**：<https://z-biz-game.github.io/z-biz-game-eulertrail-cos/>

- 零依赖、零美术、零打包器：只有 `index.html` + `css/` + `js/`，浏览器加载的就是仓库里的文件。
- 48 关已烘焙（4 档 × 12 关），每关从**序列化之后的 spec** 重解一遍：奇点数、定理笔数、构造迹数、穷举最小迹数四者一致才入库。
- 四档难度带 `par` = 2 / 3 / 4 / 5 互不重叠，副维度是实测的**错首手比例**（有多少种起手会导致这一关再也用不满预算）。
- 战役 / 每日 / 随机 / 分享链接四种入口，`#/lot/<id>` 在任何设备上都是同一个局面、同一个笔数上限。
- 本地存档（localStorage 单键），无账号、无网络请求、可离线；`node server.cjs` 只是给 ES module 一个 origin。

## 三条路：这一关的数字是谁算出来的

| 路径 | 文件 | 回答的问题 | 谁复证它 |
|---|---|---|---|
| 定理 | `js/core/theory.js` | `par = max(1, odd/2)`，`odd` 必为偶数（握手引理） | `test/theory.test.mjs`（1000 随机连通图 + 七桥度数表） |
| 构造 | `js/core/construct.js` | 这些笔数**真的画得完**：奇点配对 → 虚边 → Hierholzer 欧拉回路 → 按虚边切成 `par` 条迹 | `test/construct.test.mjs`（300 随机图：迹数 == 定理值、边不重复、并集 == 全边集） |
| 穷举 | `js/core/bruteforce.js` | 更少的笔数**确实做不到**：在 (剩余边集, 笔尖位置) 状态空间上做记忆化 DP | `test/bruteforce.test.mjs`（与定理对账；超过 14 条边就明确拒绝，不假装算过） |

关卡由 `tools/bake.mjs` 在构建期产生，浏览器永远不做生成。三条路对每一关必须一致，不一致就直接抛错
而不是丢掉这一关。`test/library.test.mjs` 每天在 CI 里把 `js/data/lots.js` 的 48 行**从序列化结果重解一遍**
（430 万个 DP 状态），手改一个 `par` 字段构建就红。

## 规则口径（界面上看得见的那三条）

- **一笔就是一条迹**：顶点可以重复经过，边不行。走到一个没有未画邻居的图钉，这一笔自己就结束了
  （定理的前提，不是礼貌规则），所以可以立刻在同一处再按下去开下一笔。
- **已经画过的边再拖过去，不生效**：不重复计数、不算失败、也不报错 —— 只是什么都没发生。
  规则层把它回报成 `{ ok: false, reason: 'drawn' }`，视图据此闪一下白，玩家看得见"为什么没反应"。
- **抬手随时可以抬，抬早了不罚**：一笔没走完也算一笔，下一笔立刻能开始。真正决定胜负的只有笔数预算：
  覆盖全部边且用完 `par` 笔 = 通关；用第 `par + 1` 笔 = 判负，但棋盘不会锁死，撤销和重置都还有效。
  按下去却一步没走就抬手，一笔都不记账。

`par`、已用笔数、覆盖边数/总边数、奇点数、`#/lot/<id>` 全都在右侧面板上，`三条路`那一行把定理值、构造迹数、
穷举迹数并排印出来 —— 玩家看不到算法，但代理看得到，`window.eulertrail.theorem` 也当场重算一遍。

难度不止看 `par`：`错首手比例` 是 `js/core/bruteforce.js` 的 `firstMoveAudit` 实测出来的 ——
枚举每一条有向起手边，数其中"走过之后就不存在 `par` 笔覆盖"的有多少。0.75 意味着四步里三步走错，
0.15 意味着这是一张一眼看得穿的图。同一档 12 关按这个数**从难到易**排，所以战役第 1 关是全池最狠的那张
（`tandem-01`：12 条边、4 个奇点、2 笔上限、75% 的起手会走错）。

## 七桥问题在这里怎么说

柯尼斯堡七桥是这条定理的反例教科书，但它**不能**当本仓的关卡：Kneiphof 岛的度数是 5，而平面格点上的一个
顶点最多只有 4 个邻居（上下左右），所以那张图无法精确嵌入本模型。`js/core/theory.js` 的 `fitsOnLattice()`
把这个事实写成可判定的断言，`test/theory.test.mjs` 用它证明"不可嵌入"而不是宣称它。仓里用的是同一定理的
4 奇点格点实例（5 条边、4 个奇点 ⇒ 2 笔），它和七桥的推理完全同形，**但它不是七桥**。

## 验收

`bash tools/verify.sh` 一条命令跑完两层，全部断言可判定：

- **node 层**（96 条）：`theory`（定理与七桥）、`construct`（构造 == 定理）、`bruteforce`（穷举对账 + 首手审计）、
  `graph`（校验器的每一类负例）、`game`（三条口径与预算）、`geometry`（≥12px 命中容差与越界钳制）、
  `library`（48 关序列化复证 + 存档：无 localStorage 时退化成内存、`best` 只降不升、`unlocked` 只升不降、清档真的清）。
- **浏览器层**（65 条）：`tools/playtest.mjs` 用零依赖 CDP 起一个真实 headless Chrome，`@boot` 检查画布真的
  出了像素（不是 300×150 默认值）与面板上的三条路一致，`@play` 走完通关/判负/评星/撤销，`@routes` 覆盖四种路由
  与越界钳制、种子可重放，`@save` 验证 localStorage 真的落盘以及两次点击的清档，`@pointer` **派发真实鼠标事件**
  （`Input.dispatchMouseEvent`，沿每条边插值多个点）把 `tandem-01` 的两笔完整拖出来，并断言：拖过已画边不重复
  计数也不记账、按在非图钉处什么都不发生、按下去不动什么都不发生、笔数超 `par` 判负但不崩、拖出图外钳在边界上
  不许穿到没走过的边。

`test/fixture.mjs` 里的期望值是手算的（度序列、`odd/2`、迹数、访问次数），不是从被测代码里读出来的；
搜索器与构造器不能给自己出题再给自己打分。

## 与 one-stroke-ios 的关系

同一个玩法、不同端、**难度口径不同**：那边关卡手写、难度凭感觉；这边关卡由生成器撒出，
难度由欧拉定理给上界、由穷举 DP 给"更少做不到"的证据、由首手审计给可比较的实数。
两边的关卡不互通（这边只承认格点上的单位横竖线段）。

## 已知边界

- 入库关卡的边数上限是 14，而不是模型允许的 60：超过 14 条边穷举 DP 就跑不动了，那一关的"更少笔数做不到"
  只剩定理论证而没有独立证据。要更大的图，得先换一个可复核的证据来源，而不是把 `MAX_EDGES` 调大。
- 每日题从整个池子里挑，所以某天可能一上来就是五笔档。这是刻意的：没有账号体系，就不做"按进度调节每日难度"。
- 通关后没有彩带、没有音效、没有分享弹窗，只有一个"分享"按钮把 `#/lot/<id>` 写进剪贴板。
- 斜边、三维、限时、笔顺唯一性、中国邮递员（最少重复路径）都不做，理由见 `DESIGN.md`。

## 上线的到底是哪一批文件

这个仓没有打包器：站点=一次文件拷贝。以前「拷哪些」写在 `pages.yml` 的 `run:` 里（手抄的几行
`cp`）。本地 `index.html` 直读仓库根，永远自洽；线上却按那份清单拷，于是页面后来引用的
`manifest.webmanifest`、`sw.js`、`icons/*` 可能一个都没上去——线上 404，而仓里的引擎测试与
真浏览器闸全绿，因为它们跑的都是仓库根，没有任何一步在「按清单拷」的那个环境下加载过页面。

现在清单只有一份，住在 `tools/assemble-site.sh`：CI 调它拷 `_site`，本地闸调它拷临时目录，
然后**对拷出来的产物**提要求（`tools/deploy-set.mjs`）：

- **W 清单与页面同源**：`pages.yml` 里必须真有 `run: bash tools/assemble-site.sh <dir>` 这一行，
  `ci.yml` 里必须真有 `run: node tools/deploy-set.mjs`。认的是调用那一行，不是文件里出现过这个
  路径——注释里本来就会写它，只 grep 字符串会被一句散文喂绿。
- **R 引用可达**：引用不靠手打名单。从 `index.html` 的 `href/src` 出发，凡解析出来是 `.js`/`.css`
  的就把那一站也扫一遍（CSS 的 `url()`、JS 去掉注释后的 `'./…'` 字面量、`new URL(x, base)` 的两种
  基、`navigator.serviceWorker.register`、`scope`），`manifest` 的 icons/screenshots/shortcuts 各自
  的 `src` 也算引用。取径上读不到的那一站本身就是红（读不到＝这一站根本没扫）。每条引用都必须在
  产物里且非 0 字节；绝对路径单列一条红，因为 Pages 挂在 `/<repo>/` 前缀下会跳出去。
- **P 位图不许说谎**：`manifest` 声明的 `sizes` 必须等于 PNG IHDR 的真实宽高——文件图标读文件头，
  内联成 base64 的图标先解码再读同一段。后一条不是可选项：图标可能住在清单里而不是盘上的 `.png`
  （有的仓另有一条"零二进制文件"的承诺，那条只约束"有没有 .png 这个文件"）；如果 P 段只筛文件名，
  声明写 512 而真图 192 就一路放行。
- **钉住两个数**：R 段实际检查的路径条数（`31`）与这一次跑的断言条数（`49`），两个数
  都钉在 `tools/deploy-set.mjs` 顶部的那对常量里。没改页面却掉了，说明解析断了；删掉一张图标会同时
  少一条 R10 与那张的 P1/P2，所以两个数一起钉，断言条数能漂就是闸在缩水的信号。这一节故意只写数值、
  不写那对常量的名字，也不写别仓文档闸的编号：有的仓的文档闸会拿"文档里出现过的同名标识号"回数它
  自己的条数，还有的会把文档里点到的每个组编号逐个核对"这一轮真的发过"——两道闸共用一个名字，
  或者在本仓的文档里出现一个本仓没有的组编号，打红的都是不相干的那一边。

`tools/deploy-set-selftest.mjs` 是这两颗钉的阳性证明：它把仓库复制到临时目录，照着每一类断言
各下一刀（X1 清单不收位图目录 / X2 模块边改名 / X3 CSS 写绝对路径 / X4 `start_url` 绝对 /
X5 删光 >=512 图标 / X6 少一个必填字段 / X7 声明尺寸与真图不符 / X8 workflow 不调脚本 /
X9 CI 不跑闸 / X10 是阴性对照——往入口 JS 追加一行只写在注释里的假路径，闸必须仍然绿、条数仍然
`31`、断言仍然 `49`；X11 og:image 退回相对路径 / X12 og:image 的前缀指向别的 slug /
X13 内联位图谎报尺寸——只在有靶子时下：X11/X12 要页面上那句 og:image，X13 要清单里真有一段 base64
图标，没有就打印 SKIP；反过来 X1 没有位图目录可砍时改砍 css，P 段一位都不核时台架直接报靶子不够），
要求每一刀都让闸**点名**变红。靶子从 `DEPLOY_SET_DUMP=1`
的出处表现挑（取径真的会读的那支 JS / 那一张 CSS，不写死某一个仓的入口名），所以页面改了、仓与仓
不同，台架跟着走。

`node tools/deploy-set.mjs` 与 `node tools/deploy-set-selftest.mjs` 就是 CI 跑的那两条命令本身
（package.json 里的 `deploy-set` / `deploy-set:selftest` 只是同一支脚本的 npm 入口）；本仓的整闸在 `tools/verify.sh` 的 `=== deploy-set ===` 那一段也各跑一次。它们红的时候并进本仓那条出口的退出码——这一条是这么证的：
把 ci.yml 里那行 `run: node tools/deploy-set.mjs` 砍掉，本仓整闸必须点名红且退出码非 0。
所以「本地全绿、线上 404 自己的 manifest / sw.js / 图标」这一类坏法在本地就会红。
